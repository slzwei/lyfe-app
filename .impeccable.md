# Impeccable Design Context — Lyfe App

Captured via `/impeccable:teach` on 2026-04-22. This is the canonical brief every design skill (`typeset`, `colorize`, `layout`, `polish`, `critique`, etc.) should read before touching the codebase.

---

## Design Context

### Users

**Primary audience:** Singapore-based financial services staff at a single insurance agency.

Five distinct personas, all using the same mobile app:

1. **Agents** (20s–40s) — on-the-go, in-hand use between client meetings. Need speed to log activities, check leads, navigate to roadshows. Often distracted, often standing, often in bright daylight.
2. **Managers** (30s–50s) — oversee teams, reassign leads, review candidate pipelines, monitor roadshow performance. Use the app between meetings on short bursts; occasional deep sessions at a desk.
3. **Directors** (40s+) — same as managers but with broader org-wide visibility. Senior eyes, value clarity over density.
4. **Personal Assistants (PAs)** — administrative role, create candidates and schedule interviews on behalf of managers. Fundamentally different job from agents/managers but currently see identical UI (biggest UX gap in the app).
5. **Candidates** (20s) — fresh recruits going through training, exams, and onboarding. Mobile-native generation. Learn the app from scratch.

**Usage context:** In-hand mobile. Never desktop. Often one-handed. Often in natural light (outdoor roadshows) or office light. Users can be tired (end of day), rushed (between meetings), or calm (evening training). The interface must work in all three moods.

**Jobs-to-be-done:**
- Agent: "Log this call outcome before I forget, then show me who's next."
- Manager: "Where's my team at this week and what needs my attention?"
- Candidate: "What's the next step in my training, and am I ready for it?"
- PA: "I need to add this new candidate and get them onto the right manager's pipeline."

### Brand Personality

**Three words:** *Warm, humane, editorial.*

**Voice & tone:**
- Speaks like a colleague who respects you. Not corporate HR, not startup-bro, not Duolingo cheerleader.
- Uses plain English. Avoids jargon ("pipeline velocity", "conversion funnel") unless the user is a manager reviewing analytics.
- Singapore-contextual. Phone numbers are +65 8-/9-prefix. Names are multi-ethnic (Chinese, Malay, Indian, Eurasian). Avoid "John Doe" — use "Siti Rahman", "Raj Kumar", "Wei Ming Lee", "Priya Selvaraj" as example copy.
- Confident but not boastful. When you do something right, the app acknowledges it warmly. When something fails, the app takes responsibility ("We couldn't reach the server, mind trying again?") not blames ("Error 500: server error").

**Emotional goals:**
- **Everyday actions** (logging a note, checking a lead) → zero friction, near-invisible UI, no emotion required.
- **Meaningful moments** (lead converted, module completed, exam passed, roadshow milestone hit) → **consistently playful and celebratory**. Small animations, warm micro-copy, occasional delight. User chose "playful and celebratory" — lean into it. But keep the register warm/editorial, not cartoonish. Terracotta confetti, not rainbow. Spring physics, not bouncy. A copy line like "Nice — that's three this week" not "WOW AMAZING 🎉".
- **Difficult moments** (exam failed, lead lost, no-show at roadshow) → supportive, not cold, not condescending. "Not this time — here's what to look at next." Never dismiss, never over-cheer.
- **Empty states** → teach the interface. "No leads yet. New ones arrive when a campaign lands — you'll get a notification." Not "No data."

**Compared to adjacent products:**
- *The Wirecutter* — trustworthy, thorough, warm, uses real names and real examples.
- *Tropic Skincare* — warm neutrals, editorial serif, makes a functional product feel like a boutique.
- *Craft Docs* / *Things 3* — native-feeling, generous touch targets, spring motion, restrained color.

### Aesthetic Direction

**Visual tone:** Editorial magazine meets iOS-native app. Warm cream surfaces, terracotta accent, a soft palette that wouldn't feel out of place on a wellness brand. Readable. Spacious. Asymmetric compositions preferred over centered layouts.

**Theme support:** Both light and dark are **required**. Default is light (SG daylight usage). Dark mode is warm-dark (`#141310`, not pure black) to match the Tropic warmth.

**References (draw from):**
- Current codebase's "Tropic Office" palette — already the strongest asset.
- Bespoke pixel-art illustrations (`PixelSeedling`, `PixelSprout`) — expand this direction; they're working.
- The existing Login screen's spring-accordion motion design — that level of craft is the benchmark.
- The existing DISC result screen's hand-coded SVG circumplex — that's the craft ceiling.

**Hard anti-references (the interface must actively avoid):**
- **AI-generated SaaS templates** — no indigo/purple gradients, no hero metric layouts (big number + small label + sparkline), no 3-equal-column card grids, no glassmorphism, no gradient text, no neon glow on dark mode, no "Elevate / Seamless / Unleash" marketing copy. Every one of these is an AI fingerprint.

**Soft anti-references (allowed as occasional inspiration, but not the default):**
- Traditional insurance (navy/white/red, stock imagery) — OK if a specific trust moment calls for it.
- Gamified learning (Duolingo) — OK for candidate training celebration, but no mascot characters, no XP/streaks.
- Dev-tool dashboards (Stripe/Linear) — OK for manager analytics density, but keep warmth in the rest of the app.

### Typography

**Currently loaded (keep):**
- `Fonts.serif` = **Fraunces** (display, editorial accents, greetings, one big hero number per screen, one italic accent per screen).
- `Fonts.mono` = **JetBrainsMono** (timestamps, IDs, short codes — never for counts, values, or labels).

**To swap (decided in teach):**
- `Fonts.sans` **Inter → something rarer.** User chose "keep Fraunces, swap Inter for something rarer." Final pick TBD during `/impeccable:typeset`.

**Candidate sans replacements** (all humanist, warm, NOT on impeccable's reject list, Google Fonts free):
- **Albert Sans** (primary recommendation) — subtle flared stems, humanist, reads as "intentionally designed" without being showy. Pairs with Fraunces' warmth.
- **Manrope** (backup) — rounded humanist, warm, very readable at small sizes.
- **Figtree** (backup) — Erik D Kennedy's newer humanist, warm feel, still uncommon.

**Intended role rules (currently violated across the codebase — must be enforced):**
1. **Serif (Fraunces)** = greetings, ONE big hero number per screen, ONE italic accent per screen. **Never** on labels, stat values, list-row names, section headers (except a hero section header), or activity items.
2. **Mono (JetBrainsMono)** = timestamps ("2m ago"), IDs (`REQ-8J2K`), short codes. **Never** on counts, percentages, currency, or UI labels.
3. **Sans (new choice)** = everything else. The workhorse.

**Scale & readability (locked in teach):**
- Body text minimum **15pt** (WCAG AA + in-hand mobile).
- Line-height 1.5+ on body, 1.2 on display.
- Touch targets **≥44pt** (iOS HIG standard).
- Hierarchy via at least 1.25 ratio between steps.
- Respect `P.letterSpacing()` — Android Roboto breaks negative tracking.

### Color

**Locked palette (keep):**
- Light base `#F5F0E6` cream, dark base `#141310` warm-dark.
- Accent `#D6552B` terracotta (+ light `#F7E7DC`, dark `#A53F1E`).
- Semantic: sage success `#7A8C6B`, butter warning `#C89B3C`, danger `#B33A2E`, dusty-slate info `#5C7A9E`.
- Tints: `tintSage`, `tintTerra`, `tintPink`, `tintButter`.

**Must fix (captured from audit):**
- **`AVATAR_COLORS` in `ui.ts:10`** currently contains `#6366F1 / #8B5CF6 / #E11D48 / #F59E0B / #06B6D4` (indigo, violet, hot magenta, amber, cyan — the exact AI-default palette). Replace with warm Tropic-family variants: muted terracotta, dusty rose, sage, ochre, clay, persimmon. `/impeccable:colorize` should own this.
- **Hardcoded hex values** across `login.tsx`, `leads/[leadId].tsx` (WhatsApp `#25D366`), `face-test.tsx`, `rejected.tsx`, `EmailVerification.tsx` → migrate to `colors.*` tokens. Add `colors.whatsappGreen` (warm-adjusted if possible).
- **Interview status colors** (`ui.ts:83`) use iOS defaults (`#34C759`, `#FF3B30`, `#AF52DE`) — retint toward Tropic.

**Rules:**
- Never pure `#000` or `#FFF` in any screen. Always theme tokens.
- Every screen must work in both light and dark mode — no module-level brand-color constants.
- Avatar + user-identity colors must stay in the warm family (no cool violets).

### Motion

- **Timing tokens (keep):** `ANIM.MICRO=200, TRANSITION=300, REVEAL=600`.
- **Easing:** exponential ease-out (`Easing.out(Easing.cubic)` or reanimated spring) — no linear, no bounce/elastic.
- **Onboarding needs motion** (currently all 6 screens are static). At minimum one `FadeInDown` spring entrance per screen.
- **Celebration motion:** terracotta-confetti bursts (not indigo), spring-physics checkmarks, pulsing "live" dots — OK for meaningful wins. Auto-dismiss (1–2s). Never loop.
- **Performance:** animate `transform` and `opacity` only. No `layout` animations on long lists.

### Spacing & Layout

- **Scale (keep):** 4pt grid `SPACING.XS=4 → XXL=24`.
- **Asymmetric layouts preferred** — top-left anchored titles, asymmetric spacing, generous right-side whitespace. No centered-everything onboarding screens.
- **Cards only when elevation communicates hierarchy.** Prefer iOS-grouped style (hairline dividers between rows) for settings, info lists, activity feeds. This is already working in `add-candidate`; apply everywhere.
- **No 3-equal-column stat grids.** Hero stats pattern banned. Find another composition (asymmetric pair, single big number + inline meta, split-screen comparison).

### Materiality

- **Shadows via `P.shadow('sm'|'md'|'lg')`** (already platform-aware — keep using).
- Hairline borders are intentional and visible (`#E6E0D1` on cream). Don't hide them.
- Radii: vary by size (chip 6–8, card 12–16, hero surface 20+). No uniform 8px-everything.

### Accessibility

- WCAG AA contrast minimum.
- Body text ≥15pt; never below 13pt even for meta.
- Touch targets ≥44pt.
- Support iOS Dynamic Type where feasible.
- Test with iOS VoiceOver for critical flows (login, lead detail, exam-taking).
- Respect `prefers-reduced-motion` on animated screens (disable decorative motion, keep functional transitions).

## Design Principles

These are the 5 principles every skill should enforce when touching this codebase:

1. **Editorial over dashboard.** When choosing between a warm magazine layout and a data-dense SaaS card grid, choose the magazine. Agents aren't SREs; managers aren't traders. Give them breathing room, a serif greeting, a readable paragraph. Stripe-style density is the fallback, not the default.

2. **Celebrate warmly, not loudly.** Every meaningful user moment deserves a beat of delight — a terracotta confetti burst, a spring check-in animation, a warm copy line ("Three this week — on fire"). But keep the register humane. Never cartoon mascots, never shouty. The register is "colleague who genuinely noticed," not "enthusiastic mobile game."

3. **Typography is role-based, not aesthetic-based.** Fraunces is a scalpel, not a brush. It gets the greeting, the one big hero number, the one italic accent — everything else is sans. JetBrainsMono is timestamps and IDs only. When in doubt, sans. This single discipline is the highest-leverage fix in the current codebase.

4. **Readable first, dense second, clever never.** Body text 15pt minimum. Line-height 1.5+. Touch targets 44pt+. An older agent in daylight on a bus must be able to use this. If a layout needs 12pt to fit, the layout is wrong — simplify, don't shrink.

5. **Every screen must live in both themes.** Dark mode is not a nice-to-have — it's the second half of the brand. No hardcoded hex at module level. Every color comes from `colors.*`. If a screen breaks dark mode, it's not done.

## Known Execution Debt (from audit 2026-04-22)

These are documented violations the next skills should systematically fix:

1. Serif-on-labels across `HeroStatsSection`, `StatCardSmall`, `RecentActivityCard`, `pipeline.tsx`, `candidates/[id]` hero. → `/impeccable:typeset`
2. Avatar palette indigo/violet → warm family. → `/impeccable:colorize`
3. PA tab is 100% delegation of Team tab with zero role differentiation. → product design work, then `/impeccable:layout` + copy pass.
4. Onboarding's centered-everything + no motion (6 screens). → `/impeccable:layout` + motion pass.
5. Candidate detail `[candidateId].tsx` is a 1,376-line single-column scroll dump. Needs tabs or collapsible sections. → `/impeccable:layout` (biggest UX win in the app).
6. Hardcoded hex colors breaking dark mode (login, WhatsApp green, face-test, rejected, EmailVerification). → `/impeccable:colorize` + `/impeccable:polish`.
7. Empty-state icons blend into cream background. → `/impeccable:polish`.
8. Personality result screens (DISC/Enneagram/VARK) have inconsistent section names + card shapes. → `/impeccable:polish`.
9. Privacy + Terms long-form text lacks max-width/line-length discipline. → `/impeccable:typeset`.

Each of these maps to a future skill invocation. They're not done yet — this file just captures what the audit found so skills know where to look.

## Shared Design System (extracted 2026-04-22)

Tropic is now a shared source-of-truth package at `/lyfe-master/lyfe-design/`. Lyfe-app is the primary consumer and the aesthetic is anchored here — but mktr-platform (web admin) now consumes the same palette, typography, spacing, motion, and semantic tokens via a Tailwind preset and CSS variables.

- Source: `lyfe-design/src/colors.ts`, `typography.ts`, `typography.native.ts`, `spacing.ts`, `motion.ts`, `shadows.native.ts`, `avatar-palette.ts`, `semantic.ts`
- Synced to: `lyfe-app/design/` (imported via `@/design/*`)
- lyfe-app's `constants/Colors.ts`, `constants/type.ts`, `constants/ui.ts` are thin re-exports — editing them should be done in `lyfe-design/src/` upstream.

**Implication for skill runs:** When an `/impeccable:*` skill proposes a token change (e.g., tweak a semantic color, adjust a spacing step), make the change in `lyfe-design/src/*.ts`, then run `npm run sync:design` from `lyfe-master/`. The change lands in every consumer atomically.

The canonical cross-project Design Context lives at `/lyfe-master/.impeccable.md`. This file remains the definitive lyfe-app-specific brief.
