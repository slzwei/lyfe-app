What's different from the Manager view →

PAs don't own candidates — they coordinate across them. So the Home sections reframe as task queues: chase missing things, schedule calendar items, file paperwork. Three key shifts from the manager mockup:

Section labels change from relationship → admin

  • "Needs you" → "Needs chasing" — still red, but now means "admin follow-up needed" not "call them". Stuck invites, missing documents, expiring deadlines.
  • "This week" → "Schedule this week" — calendar-booking tasks. The interview isn't on the calendar yet; the exam slot isn't booked; the BDM interview needs a director's availability.
  • "Ready" → "File & submit" — sage-coloured, paperwork-ready candidates. RNF applications, BES intake forms, MAS submissions.

Rows show which manager each candidate belongs to

  • PAs typically support 2–4 managers. "Sarah Rahman · Wei Ming" lets the PA triage by manager if they want to batch work per manager.
  • Manager names are coloured info-blue so they pop visually — easy to scan down the column.

Stats card at top speaks admin, not pipeline

  • Manager sees: "13 candidates · 3 new leads · 28% conversion" (performance metrics)
  • PA sees: "8 admin tasks today · supporting 3 managers · 28 candidates" (workload metrics)

Actions would differ inside each row (if we added inline buttons)

  • Manager row actions: Call · WhatsApp · Schedule · (relationship-focused)
  • PA row actions: Send request · Book slot · Prepare form · (admin-focused)
  • No "Call" from PA — PAs don't call candidates; their manager does.

What stays the same

  • Tropic palette, Albert Sans/Fraunces/JetBrainsMono, boxed-card layout — visually consistent across roles.
  • Row pattern (stripe · byline · next step · time signal) — identical mechanics, different content.
  • Tap row → candidate detail. Tap "See all →" → full pipeline view (same two destinations).
  • No manager-logging required — all task triggers come from system state.
